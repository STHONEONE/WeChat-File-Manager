# V1.3.0 开发记录

基线为 V1.2 main `cb7f4c6406919bca8940b1628e0b6e92157ab232`，开发分支 `feature/v1.3`。集中实现、统一测试与提交，最终通过 PR 合并到 main，不建立发布标签或 Release，不制作 EXE/ZIP。

## 目录模型

`directory_mapper.py` 以账号根目录的相对路径匹配已确认角色。目录别名只影响显示，不改变权限判断。未知层级保留名称，标注用途未确认。中文分类只是指向同一真实路径的虚拟导航，真实视图保持原层级，仍按需加载。目录详情与文件跳转复用原索引，目录备注保存在本机数据库。

## 删除计划与执行

`delete_service.py` 只为索引中的普通文件创建短时、一次性计划。准备阶段检查路径范围、格式、链接、属性、身份和可用回收站；确认界面展示完整选择范围，用户确认清单并额外确认原始附件的路径引用风险。重复项不自动选择，清理前重新使用 V1.2 的流式哈希算法验证内容。

执行时先写入 pending 审计，再重新校验；`windows_recycle.py` 固定祖先目录句柄，文件句柄拒绝共享写入，通过现代 IFileOperation 回收标志及 PreDeleteItem 回调否决非回收操作。只有有效成功 HRESULT 与回收站新条目回执才确认成功。没有 SHFileOperation、unlink 或永久删除回退。收到失败/取消或无法确认时逐项记录，不推断已释放空间或自动恢复。

成功后复用事件索引更新，保留用户备注、标记缺失、使旧哈希失效，更新列表和已加载目录计数。审核记录只在本机 SQLite 中，设置提供记录查看和打开系统回收站入口。

## 数据迁移

schema 5 增加目录备注、删除记录及每账号最近成功扫描时间，沿用既有升级前自动备份。旧版本个人信息保留。目录暂时消失后再次扫描时可由 settings 中的备注映射恢复自定义信息。

## 验证边界

测试和原生回收验证只使用独立模拟目录。默认界面自检不调用实际删除；原生回收探针必须显式提供 --run-native，且只能新建自己在本项目 .tmp 下的夹具。本轮不支持未登记来源的外部归档副本清理，不自动“保留一份”。Windows 10 保持待验证。
