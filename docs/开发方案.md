# 微信文件管理器 V1.0 项目开发方案

**项目名称：** 微信文件管理器（WeChat File Manager）

**目标平台：** Windows 10 / Windows 11

**项目类型：** 本地桌面应用程序

**开发语言：** Python

**项目基础：** [oracis/wechat-file-organizer-gui](https://github.com/oracis/wechat-file-organizer-gui)

**最终交付：** Windows EXE 程序、完整源代码、使用说明、测试报告

**版本定位：** V1.0 正式基础版

---

## 一、项目背景与开发目标

### 1.1 项目背景

Windows 微信会将聊天文件、图片、视频及部分内部数据保存在本地目录中。由于不同微信版本采用的目录结构存在差异，并且部分目录使用英文名称、账号编号或内部标识，用户通过 Windows 文件资源管理器查找文件时比较困难。

微信自带文件管理功能可以解决部分查找问题，但在跨账号统一浏览、自定义备注、长期收藏和本地文件索引等方面仍有扩展空间。

### 1.2 项目目标

开发独立的 Windows 微信文件管理器，在不修改微信程序和原始文件目录的前提下，为用户提供统一的中文文件管理界面。

项目主要实现以下目标：

1. 将复杂的微信目录转换为容易理解的中文虚拟目录。
2. 自动识别微信本地文件，建立统一的文件索引。
3. 支持跨目录、跨账号的文件搜索及分类筛选。
4. 支持为文件和目录添加备注、别名、标签及收藏状态。
5. 支持文件预览、打开和快速定位。
6. 统计微信文件数量、存储空间及文件类型分布。
7. 提供安全的文件复制和导出功能。

**核心设计原则：原始文件不移动、不重命名、不自动删除，所有中文名称、备注和标签只存在本程序中。**

## 二、软件界面设计

采用接近 Windows 11 文件资源管理器的桌面界面，重点突出中文目录导航和文件检索功能。

### 2.1 主界面布局

主界面分为五个区域。

**顶部工具栏：** 展示软件名称、全局搜索框、文件类型筛选、微信账号切换、刷新索引及设置入口。

**左侧导航栏：** 展示“全部文件、收到的文档、图片、视频、音频、压缩文件、收藏、我的标签、微信原始目录”等入口。同时支持查看每个微信账号对应的目录结构。

**中央文件列表：** 使用类似资源管理器的表格视图，展示文件名、类型、大小、修改时间、所属账号及标签。支持排序、多选和右键菜单。

**右侧文件详情栏：** 展示所选文件的基本信息、图片预览、原始存储路径、用户备注、标签和收藏状态。

**底部状态栏：** 显示当前文件数量、选中文件数量、总占用空间及扫描状态。

### 2.2 目录展示规则

程序使用两套目录概念：

- **真实目录：** 微信程序实际使用的磁盘路径，不允许通过本软件重命名。
- **虚拟目录：** 本软件根据文件类型、目录规则和用户备注生成的中文视图。

例如：

真实路径：`D:\xwechat_files\账号目录\msg\file\2026-10`

虚拟路径：`我的微信 → 收到的文档 → 2026年10月`

虚拟目录不代表磁盘中真的创建了这些文件夹。

对于无法可靠识别用途的目录，显示原始名称，并允许用户手动设置中文别名，不凭猜测将目录识别为某个联系人或聊天群。

## 三、V1.0 功能需求

### 3.1 微信目录识别

程序启动时尝试识别本机微信文件存储路径，兼容常见的新旧 Windows 微信目录结构。

功能要求：

- 支持自动发现常见微信文件根目录。
- 支持手动选择自定义微信文件目录。
- 支持同时添加多个微信账号目录。
- 支持为账号设置名称和备注。
- 支持保留并查看真实目录路径。
- 对不支持的目录结构给出明确提示。

### 3.2 中文目录管理

为已识别的文件类型及目录提供中文解释和分类视图。

默认分类包括文档、图片、视频、音频、压缩文件及其他文件。

此外，提供独立的“原始目录结构”视图，允许浏览微信内部文件夹，并查看目录名称、原始路径、文件数量和占用空间。

缓存目录、数据库目录等特殊区域仅进行安全的元数据统计，不尝试自动打开、解析或修改内部数据库。

### 3.3 全局文件搜索

为可识别的文件建立本地索引，实现快速搜索。

搜索条件包括：

- 文件名及扩展名。
- 文件类别。
- 所属微信账号。
- 修改时间范围。
- 文件大小范围。
- 用户添加的标签和备注。

支持多条件组合筛选，以及根据文件名、时间和大小排序。

V1.0 的搜索范围主要是文件名和索引元数据，不包括 Word、PDF 等文件的正文内容。

### 3.4 文件预览与打开

支持直接显示常见图片格式的缩略图和预览图，包括 JPG、PNG、WebP 等。

对于 Word、Excel、PPT、PDF 等文档，V1.0 默认调用 Windows 已安装的关联程序打开，不自行实现完整的文档渲染器。

提供“打开文件”“打开所在文件夹”“复制文件路径”等快捷操作。

无法识别或加密的文件显示文件信息和提示，不强行解析。

### 3.5 备注、别名、标签与收藏

支持用户为微信账号和目录设置自定义中文别名。

支持对单个文件填写备注、添加多个标签及设置收藏状态。例如，将某个 PDF 文件标记为“科研”和“论文”，以后可以直接通过标签找到该文件。

这些信息存入独立的 SQLite 数据库，不写入微信原始文件，也不依赖修改文件名。

### 3.6 文件统计

提供简洁的文件统计面板，展示文件总数、总占用空间、分类数量及不同微信账号的存储情况。

同时支持查看指定目录的空间占用，帮助用户识别大文件和占空间较多的文件类型。

统计仅作分析用途，V1.0 不提供直接清理微信原始文件的操作。

### 3.7 文件索引管理

首次使用时进行完整扫描，建立 SQLite 文件索引。

后续支持手动刷新和启动时增量扫描，根据文件路径、大小及修改时间判断是否需要更新记录。

当原始文件被微信或用户在外部删除时，索引应能检测并标记文件已不存在，避免继续显示不可用的文件为正常状态。

扫描任务在后台工作线程运行，防止文件数量较多时界面卡死。

### 3.8 文件复制与导出

支持选择一个或多个文件，复制到用户指定目录。

支持按文件类型或月份创建归档副本，并生成包含文件名、原始路径及复制路径的 CSV 清单。

复制失败必须提示原因，不删除或替换源文件。对于目标文件重名的情况，提供自动更名或跳过选项。

## 四、技术架构

### 4.1 技术选型

| 技术 | 用途 |
|---|---|
| Python 3.11+ | 主要开发语言 |
| PySide6（Qt） | Windows 桌面图形界面 |
| SQLite | 保存索引、备注、标签及配置 |
| Pillow / Qt 图像组件 | 图片预览与缩略图处理 |
| pathlib / os / shutil | 本地目录扫描及安全复制 |
| PyInstaller | 打包 Windows EXE |
| pytest | 自动化功能测试 |

采用 PySide6 的主要原因是更容易实现现代桌面布局、可调整大小的多面板界面及大文件列表。

原开源项目使用 Tkinter，因此本项目不直接复用原有界面，而是优先复用其微信目录发现、文件扫描和分类逻辑，重新实现图形界面。

### 4.2 代码模块划分

项目按照以下模块组织：

```text
wechat-file-manager/
├── app/
│   ├── main.py              # 程序入口
│   ├── ui/                  # 图形界面
│   ├── scanner/             # 微信目录识别和扫描
│   ├── indexer/             # 文件索引与更新
│   ├── database/            # SQLite 数据访问
│   ├── services/            # 搜索、分类、标签、导出
│   └── utils/               # 路径、日志及公共工具
├── assets/                  # 图标及界面资源
├── tests/                   # 自动化测试
├── docs/                    # 项目文档
├── LICENSE                  # 许可证
├── requirements.txt         # Python 依赖
└── build.bat                # Windows 构建脚本
```

模块之间尽量减少直接依赖，以便将来增加文件全文搜索、重复文件检测或其他功能时，无需重新开发整个软件。

### 4.3 数据存储设计

SQLite 至少包含以下数据实体。

| 数据实体 | 保存内容 |
|---|---|
| accounts | 微信账号标识、真实目录、显示名称、备注 |
| directories | 原始路径、中文别名、目录类型 |
| files | 文件路径、名称、类型、大小、时间、状态 |
| tags | 用户自定义标签 |
| file_tags | 文件与标签的关联关系 |
| favorites | 收藏关系 |
| notes | 文件备注 |
| settings | 扫描范围、界面偏好、其他配置 |

文件路径采用规范化绝对路径进行唯一性管理。文件的实际内容不保存到数据库中，数据库只保存索引及用户维护的信息。

需要考虑文件重命名、移动及删除等情况下的索引更新，避免备注与其他文件发生错误关联。

## 五、开发实施步骤

### 第一阶段：基础工程与扫描模块

建立独立项目结构，整理原开源项目中可以合法复用的扫描逻辑，并保留 MIT 许可证要求的版权声明。

完成新旧微信目录识别、多账号扫描、文件类型判断、SQLite 索引写入及基础扫描测试。

**阶段验收：** 能正确扫描指定微信目录，识别文件数量并建立本地索引。

### 第二阶段：桌面主界面

使用 PySide6 开发主窗口，包括左侧导航树、顶部搜索栏、中央文件表格、右侧详情面板及底部状态栏。

完成虚拟中文目录与真实目录的映射，实现不同文件类别之间的切换。

**阶段验收：** 能在软件中浏览已索引的文件，查看详细路径，并打开真实文件。

### 第三阶段：搜索与个性化管理

实现文件搜索、多条件筛选、排序、自定义目录别名、标签、备注及收藏功能。

所有个人设置均保存在 SQLite 中，软件关闭后再次打开仍能读取。

**阶段验收：** 用户能够快速查找目标文件，并且备注、标签等信息不会丢失。

### 第四阶段：预览、统计与导出

加入图片预览、文件统计、目录空间分析、多选复制及 CSV 导出功能。

对大文件、重复文件名和无法访问的文件设计合理的处理机制。

**阶段验收：** 能稳定完成文件浏览、预览和安全复制，不修改微信原始目录。

### 第五阶段：优化、测试与打包

重点测试大量文件扫描、程序重启、路径变化、不同微信版本目录，以及文件被占用或删除时的表现。

完成 Windows EXE 打包、程序图标、基础使用说明和软件版本信息。

**阶段验收：** 在目标 Windows 系统中，无需安装 Python 即可运行并完成 V1.0 核心功能。

## 六、安全与可靠性要求

1. 默认只读扫描微信目录，不修改微信聊天数据库及内部数据文件。
2. 不实现自动删除微信原始文件，也不提供源文件批量删除入口。
3. 所有备注、收藏及标签只修改本软件的 SQLite 数据库。
4. 扫描应处理无权限、文件被占用、文件消失、路径过长等异常。
5. 避免目录联接、符号链接造成重复扫描或无限递归。
6. 用户数据默认仅存储在本地，不上传文件及索引。
7. 用户可以导出或备份自己的备注和索引数据。
8. 文件复制操作应明确展示源路径与目标路径，并报告成功和失败数量。

## 七、测试与验收标准

第一版以约 5,797 个文件作为初始测试规模，并增加更大规模的模拟文件集进行压力测试。

验收至少覆盖以下场景：

| 测试场景 | 合格标准 |
|---|---|
| 首次扫描 | 文件正确入库，界面保持响应 |
| 多账号扫描 | 不同账号文件能够正确区分 |
| 中文目录 | 中文别名与真实路径对应正确 |
| 文件搜索 | 结果符合筛选条件 |
| 标签和备注 | 软件重启后数据保持一致 |
| 增量扫描 | 新增文件进入索引，删除文件状态正确更新 |
| 文件预览 | 支持的图片正常显示，不支持的格式明确提示 |
| 文件复制 | 源文件保持不变，复制结果可核验 |
| 异常情况 | 遇到权限错误、占用文件等不会导致程序崩溃 |
| EXE 运行 | 无 Python 开发环境也可正常启动 |

## 八、V1.0 不包含的功能

为控制开发范围，以下功能不进入第一版：

- 微信聊天记录数据库的读取和解密。
- 自动获取文件所属联系人或聊天群。
- 对微信原始文件进行删除、迁移和重命名。
- PDF、Word 等文档的正文全文搜索。
- 自动解码微信私有加密附件。
- 自动去重清理与磁盘空间释放。
- 云同步及多设备数据同步。

这些功能可以根据 V1.0 的实际使用情况，选择性纳入后续版本。

## 九、最终交付内容

项目最终交付以下成果：

**1. 可执行程序：** 可以双击运行的 Windows EXE，具备完整的 V1.0 文件管理功能。

**2. 源代码：** 包含图形界面、扫描器、索引模块、数据库和辅助工具的完整 Python 项目。

**3. 开发文档：** 包含项目结构、依赖安装、调试方法和 EXE 打包说明。

**4. 用户使用说明：** 说明如何选择微信目录、搜索文件、添加标签、管理收藏和导出文件。

**5. 测试结果：** 记录主要功能测试、异常场景及已知限制。

## 十、版本完成标准

当软件能够稳定完成微信文件扫描、中文目录浏览、全局搜索、文件预览、备注收藏、索引更新及安全复制，并能在 Windows 上独立运行时，即达到 V1.0 的发布要求。

项目后续优先围绕搜索效率、目录兼容性和使用体验持续完善，而不是一开始就加入复杂的微信数据库解析或系统清理功能。

**最终目标：让微信文件像普通 Windows 文件一样容易查找和管理，同时不破坏微信本身的目录结构和正常使用。**
