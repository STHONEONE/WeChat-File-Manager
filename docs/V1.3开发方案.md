# 微信文件管理器 V1.3 开发方案

**项目名称：** WeChat File Manager

**目标版本：** V1.3.0

**版本主题：** 微信目录中文化与文件清理

**开发基础：** V1.2 完成后的代码

**目标平台：** Windows 11，兼顾 Windows 10

**开发模式：** 集中开发、统一测试、统一提交

**GitHub：** https://github.com/STHONEONE/WeChat-File-Manager

---

## 一、版本定位与开发目标

### 1.1 项目核心定位

本项目主要服务于个人使用，目的是解决 Windows 微信本地文件存储结构复杂、目录命名不直观、文件难以定位及重复文件占用空间等问题。

软件不需要发展为完整的第三方微信客户端，也不需要加入大量与目录管理无关的功能。

V1.3 在 V1.2 重复文件检测、文件索引和空间统计的基础上，重点解决两个实际问题：

**第一，看懂微信文件夹。** 用户可以通过中文名称和用途解释，快速了解聊天数据库、图片、视频、文档、缓存等数据的存储位置。

**第二，清理不需要的文件。** 用户可以删除指定文件，批量处理重复文件，并尽可能避免误删重要微信数据。

### 1.2 开发原则

1. 不修改微信原始目录名称和层级。
2. 中文目录名称仅存在于本软件中。
3. 文件删除必须由用户主动触发。
4. 优先使用 Windows 回收站，不提供默认永久删除功能。
5. 微信内部数据库、配置文件及无法确认用途的系统文件禁止通过本软件删除。
6. 保持 V1.0 至 V1.2 的现有功能及个人数据兼容。
7. 不为增加功能数量而引入无关模块。

## 二、核心功能一：微信目录中文化

### 2.1 目录用途识别

完善现有微信目录识别机制，根据不同微信版本的已知目录结构，为能够确认用途的目录提供中文名称。

参考分类如下：

| 原始目录或类型 | 中文解释 | 管理方式 |
|---|---|---|
| `msg` | 聊天相关数据目录 | 展示与定位 |
| `msg/file` | 聊天文件存储目录 | 浏览与管理可识别文件 |
| `FileStorage/File` | 旧版微信聊天文件 | 浏览与管理可识别文件 |
| `FileStorage/Image` | 旧版微信图片资源 | 浏览可读取图片 |
| `FileStorage/Video` | 旧版微信视频资源 | 浏览可识别视频 |
| `db_storage` | 微信数据库相关目录 | 只读展示与统计 |
| `cache` | 缓存目录 | 只读展示与统计 |
| 其他未知目录 | 保留原始名称 | 允许自定义备注 |

以上为候选识别规则，实际含义需要依据微信版本和真实目录结构验证。

不能仅依靠目录名称，就断言其中包含全部聊天记录或全部图片。

### 2.2 中文目录树

在软件左侧提供清晰的目录导航，支持两种查看方式。

**中文分类视图：**

```text
我的微信文件
│
├── 常用微信账号
│   ├── 聊天记录数据库
│   ├── 聊天图片
│   ├── 聊天视频
│   ├── 收到的文档
│   ├── 缓存与临时文件
│   └── 其他数据
│
├── 第二个微信账号
│   └── ...
│
└── 重复文件
```

中文分类视图是虚拟结构，不在磁盘中创建或移动文件夹。

**真实目录视图：**

保持微信实际文件夹层级，支持展开、折叠和查看完整路径。

两种视图可以切换，同一个目录的中文解释与真实路径应当始终对应。

### 2.3 目录详情

选中目录后，右侧显示：

- 中文名称和原始名称。
- 目录用途及说明。
- 完整磁盘路径。
- 文件数量和目录占用空间。
- 最近一次成功扫描时间。
- 当前目录的识别状态。

提供“打开实际目录”和“复制目录路径”功能。

对于识别依据不足的目录，显示“用途尚未确认”，不自动赋予错误名称。

### 2.4 自定义名称

延续现有目录别名功能，支持用户自行修改中文显示名称。

例如，将一个难以理解的账号编号目录显示为“常用微信账号”。

别名、备注保存在 SQLite 中，不修改真实目录名称。

## 三、核心功能二：文件删除与批量清理

### 3.1 单个文件删除

在普通文件列表中增加“移入回收站”操作。

用户选中文件后，可以通过右键菜单执行删除。

操作前显示文件名、原始路径及相关风险提示。

删除成功后更新文件索引，并将文件状态标记为已删除或已不存在。

### 3.2 批量删除

支持通过 Ctrl、Shift 或多选方式选择多个文件，统一执行删除。

删除前展示确认窗口，包含：

- 选中的文件数量。
- 文件大小总和。
- 涉及的微信账号。
- 目标文件清单。
- 预计移入回收站的空间量。
- 是否包含微信管理的原始附件。

用户确认后执行。

对于正在使用、权限不足或删除失败的文件，程序应跳过并记录错误，不影响其他文件的处理。

### 3.3 重复文件批量清理

复用 V1.2 的重复文件检测结果，不重新实现重复文件识别算法。

在“重复文件”页面中，按文件内容哈希分组展示重复文件。

每个重复组显示文件数量、单个文件大小、所属账号和具体路径。

用户可以展开重复组，勾选不需要保留的文件，然后批量移入回收站。

对于软件创建且可以确认来源的归档副本，可以提供“保留一份、选择其余副本”的辅助功能。

**对于微信管理的原始附件，不自动勾选任何待删除文件。** 即使文件内容完全一致，不同聊天也可能分别引用各自的原始路径。仅保留一个内容副本，并不意味着其他路径可以安全删除。

因此，原始附件必须由用户主动选择，并经过额外风险确认才能执行批量删除。

### 3.4 删除前安全校验

执行删除前必须进行以下检查：

1. 确认文件仍然存在。
2. 确认路径位于允许管理的范围。
3. 排除微信数据库、配置文件及明确禁止删除的内部资源。
4. 排除目录联接、符号链接等可能造成路径越界的对象。
5. 检查文件大小、修改时间和身份信息是否变化。
6. 对重复文件清理中的选定对象重新验证内容哈希。
7. 确认删除操作不会误处理未选中的文件。
8. 对正在写入或状态发生变化的文件停止删除并报告原因。

文件内容重复仅作为筛选依据，不能作为文件可以安全删除的充分条件。

### 3.5 回收站机制

V1.3 所有删除操作默认通过 Windows 系统回收站完成。

不使用直接永久删除作为失败回退方案。

对于不支持回收站的网络路径、特殊设备或其他文件系统环境，程序应拒绝删除并给出说明。

软件提供“打开 Windows 回收站”入口，方便用户自行恢复文件。

需要特别说明，文件移入回收站后通常不会立即释放全部磁盘空间。统计界面不能把待删除容量直接显示成已经释放的容量。

### 3.6 删除记录

建立本地删除操作日志，记录：

- 操作时间。
- 原始文件路径。
- 文件大小。
- 所属重复组（如有）。
- 删除执行结果。
- 失败或跳过原因。

记录用于核对操作结果，不意味着软件能够保证自动恢复所有已删除文件。

删除日志同样只保存在本机，不上传至服务器。

## 四、核心功能三：文件定位与管理体验

### 4.1 快速定位

保留并优化“打开所在文件夹”功能。

对于普通文件，尽可能调用 Windows 文件资源管理器并选中对应文件。

对于目录，直接打开其真实位置。

### 4.2 目录与文件关联

在中文目录中选择某一分类时，中央列表展示对应的可管理文件。

用户选中某个文件，可以查看其真实路径和上级目录。

支持从文件详情跳转到对应的真实目录视图，减少手动逐级查找文件夹的操作。

### 4.3 界面调整

沿用现有 PySide6 桌面界面。

V1.3 不进行全面视觉重设计，只增加必要的目录详情、删除确认和重复文件清理界面。

普通浏览操作不应频繁弹出窗口；涉及原始文件删除时，必须使用明确的确认界面。

## 五、技术实现方案

### 5.1 复用现有模块

继续使用 V1.2 已有的 SQLite 索引、重复文件检测以及后台扫描机制。

重点新增或完善以下模块：

| 模块 | 主要职责 |
|---|---|
| Directory Mapper | 目录识别、中文名称映射与用途解释 |
| Directory View | 中文视图、真实目录视图与详情 |
| Delete Service | 删除权限检查、回收站调用、执行记录 |
| Duplicate Cleanup | 重复文件选择、清理计划及安全校验 |
| Delete Dialog | 删除确认、风险提示与结果展示 |

具体代码目录由现有 V1.2 项目架构决定，避免为了模块划分而进行不必要的重构。

### 5.2 Windows 回收站

优先采用可靠的 Windows Shell 回收站接口或经过验证的兼容库实现。

删除接口应返回明确的成功、失败或取消状态。

不允许因为回收站调用失败而自动转为永久删除。

### 5.3 SQLite 数据兼容

新增删除日志及必要的目录用途映射信息。

若需要改变现有表结构，必须通过数据库版本迁移完成。

数据库迁移不得丢失现有文件标签、目录别名、收藏记录及备注。

### 5.4 与 V1.2 衔接

开始 V1.3 编码前，先确认 V1.2 是否已经合并至 main，并检查重复文件检测模块的实际接口。

如果 V1.2 的实现与原开发方案存在差异，应以真实代码为基础调整接入方式，避免重复实现哈希计算和索引管理逻辑。

## 六、安全边界

V1.3 虽然新增文件删除能力，但必须明确区分普通文件与微信内部资源。

**可以进入删除流程的对象：**

- 用户明确选择的可识别普通文件。
- 软件创建并可以确认来源的归档副本。
- 经用户逐项选择、确认风险且通过安全检查的微信原始普通附件。

**禁止通过本软件删除的对象：**

- 微信聊天数据库及其关联文件。
- 微信程序配置文件及关键内部数据。
- 无法可靠确定用途的加密或专有内部文件。
- 正在使用且无法确认安全状态的文件。
- 整个微信账号目录及系统内部目录。

不实现一键清空微信目录、删除全部缓存或永久删除全部重复文件等高风险功能。

## 七、开发安排

V1.3 继续采用集中开发模式。

**第一部分：目录中文化与定位。** 完善目录映射规则，建立中文目录视图和真实目录视图的对应关系，补充目录用途说明。

**第二部分：删除功能。** 实现单文件删除、批量删除、回收站调用、安全校验和删除记录。

**第三部分：重复文件清理。** 接入 V1.2 重复文件检测结果，实现重复组展示、文件选择和批量清理。

**第四部分：界面整合与测试。** 统一调整相关界面，执行自动化测试和 Windows 原生交互验证，修复发现的问题。

本轮不要求每完成一个模块就进行完整验收。开发过程中可以针对文件删除及数据库迁移进行必要的安全检查，最后统一运行完整测试。

## 八、验收标准

| 验收项目 | 通过标准 |
|---|---|
| 中文目录 | 已识别目录中文名称与真实用途对应准确 |
| 原始目录 | 可以查看原始路径，不改变真实目录结构 |
| 目录详情 | 文件数量、大小和位置能够正确展示 |
| 单文件删除 | 指定文件成功移入回收站，其他文件不受影响 |
| 批量删除 | 仅处理用户确认的文件，提供逐项结果 |
| 重复清理 | 能够基于 V1.2 结果选择并清理重复文件 |
| 安全保护 | 微信数据库及内部关键资源不能被误删 |
| 文件变化 | 删除前状态变化的文件能够被安全跳过 |
| 索引同步 | 删除成功后文件列表和统计能够更新 |
| 数据兼容 | V1.2 已有备注、标签和收藏完整保留 |
| 异常处理 | 权限拒绝、回收站不可用、文件占用时不永久删除 |
| 回归测试 | 现有搜索、扫描、预览和复制功能继续正常工作 |

删除功能必须使用独立的模拟微信目录进行完整测试，覆盖跨账号重复文件、删除部分成功、文件被占用、文件正在变化、回收站不可用及用户取消等情况。

在通过模拟目录测试前，不允许将真实微信文件作为批量删除实验对象。

## 九、暂不开发的功能

V1.3 不加入：

- AI 智能分类。
- PDF、Word 全文搜索。
- 微信聊天数据库解密。
- 联系人和群聊自动识别。
- 云端文件同步。
- 自动清空缓存。
- 文件永久删除和磁盘彻底擦除。
- 与目录管理无关的新功能。

## 十、GitHub 提交与交付

完成开发后，集中进行测试和问题修复。

更新 README、CHANGELOG、V1.3 开发方案及测试报告。

将通过验收的改动统一合并到 GitHub main 分支，保留已有 Git 历史。

本轮不创建 GitHub Release，不制作正式 EXE 或 ZIP 发行包，保留现有本地运行和构建能力。

**V1.3 最终完成标准：用户能够清楚理解微信目录的用途，快速定位真实文件，并且能够在风险明确、操作可核对的前提下，批量清理自己不需要的文件和重复副本。**
