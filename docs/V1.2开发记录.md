# V1.2.0 开发记录

基线：V1.1 main `26756e7ff1bc6693248dd7c0cf7cdd5d66d7f0d9`；开发分支 `feature/v1.2`。本轮集中集成、统一测试，最终通过 PR 将完整改动统一合并到 main。不发布安装包、ZIP 或 GitHub Release。

## 增量和一致性

完整扫描为每个账号构建元数据快照后比较旧索引，只有新增、修改、删除的文件才写入文件表。目录聚合不变时不更新目录记录。当前账号的写入以事务提交，取消会回滚，访问失败不执行删除推断。事件更新按路径合并，维护可管理文件和祖先目录的数量/大小；目录结构变更、积压或定时校正使用完整扫描。

## 哈希与重复组

仅针对相同大小的候选做串行流式 SHA-256。缓存绑定大小、纳秒修改时间、ctime 和文件身份，计算前后检查稳定性，缓存复用前重新核对磁盘属性。只保存有效结果；不稳定、不可访问或索引已过期时失效并跳过。检测可取消，已验证的缓存保留，整体结果标记为未完成。重复组动态查询有效缓存并与当前文件元数据匹配，不维护额外的组副本。

## 监控与界面

watchdog 使用 Windows 原生事件。事件队列最多 2,000 个去重路径，防抖合并，积压回退全量校正；目录变更及每 15 分钟再次校正。观察线程、索引线程和 Qt 信号桥分离。开启状态持久化，重启会先校正，不假设监控永久无遗漏。主窗口有未保存编辑时只提示索引已更新，不刷新掉用户输入。

重复文件与统计采用独立窗口，复用原文件模型和归档操作。新增入口为最近文件、重复文件、大文件及统计。批量管理支持所选路径或当前全部筛选结果，整笔事务可取消并反馈实际数量。

## 数据库与隐私

schema 4 新增文件纳秒属性、hash_cache 和 account_scan_state。旧数据库升级前自动保存一致备份；所有原有备注、标签、收藏、别名和账号设置保留。哈希、路径、文件内容和个人设置仅存本地 SQLite，测试报告与公开截图只含虚构数据。

实现模块：`snapshots.py`、`scanner.py`、`duplicate_detector.py`、`file_monitor.py`、`statistics.py`；界面模块为 `ui/duplicates.py`、`ui/statistics_view.py` 及原窗口的渐进扩展。
