## V1.1 / V1.2 同机性能对比

硬件：Intel Core Ultra 5 125H，18 个逻辑处理器，31.6 GiB RAM。两个版本读取同一目录的 2,000 个四字节虚构文件。耗时不启用 SQL 跟踪；写语句次数在另一次扫描中单独跟踪。

| 指标 | V1.1 | V1.2 |
|---|---:|---:|
| 首次扫描 | 0.7967 s | 0.7295 s |
| 未变化目录再次扫描 | 0.7302 s | 0.6760 s |
| 再次扫描的文件表写 SQL 语句数 | 2,001 | 0 |
| 50,000 条索引，首批 200 条中位数 | 17.393 ms | 17.192 ms |
| 中文备注查询中位数 | 33.626 ms | 33.236 ms |
| 末页查询中位数 | 37.469 ms | 36.396 ms |

说明：V1.2 仍需遍历与读取文件属性，不能把文件表零写入理解为完全不访问磁盘或 SQLite。扫描状态仍会更新。首次扫描及重复扫描时长会受系统缓存与进程调度影响；查询延续 V1.1 的分页性能，不声称大幅加速。

哈希数据集：44 个模拟文件，包含 20 对相同的 8 KiB 文件、2 个空文件和 2 个相同的 4 MiB 文件。首次检测 0.5760 秒、计算 44 个哈希；再次检测 0.1742 秒、重新计算 0 个，候选缓存命中率 100%。

原生监控到索引可查询的 3 次延迟：1,272.816 / 1,089.332 / 1,145.495 ms。该基准防抖为 0.2 秒，产品默认 0.6 秒，不能将基准延迟当作默认设置的承诺。

数据见 [V1.2性能测试.json](V1.2性能测试.json)。复现：

## 已知限制

- 文件系统事件不保证永久无遗漏。启用监控会在启动/重启、目录变化或积压时校正，平时每 15 分钟全量校正；始终保留手动扫描。
- 默认关闭监控，设置中开启后记住开关。异常可重启或手动更新；监控不自动启动全盘内容哈希。
- 哈希结果表示最近一次元数据一致的校验状态；不是防篡改机制。刚写入或有变化的文件会跳过，需稳定后重试。
- 统计的内部目录容量来自最近全量扫描；事件增量只更新可管理文件。未完成扫描、访问异常或哈希跳过都显示不完整提示。
- 理论冗余不等于可释放空间，硬链接和压缩文件系统可能已共用物理空间。本程序没有源文件清理入口。
- 大规模事件和单账号数据库提交可能短暂等待。分页结果受到外部变动影响，批量处理后尽量保留筛选条件和当前首批内的选择，必要时手动刷新。
- Windows 10 与独立无 Python 发行包未在本轮验收；没有为本轮生成发行包。
