## 原生 Windows 回收站验证

先通过独立夹具的模拟删除安全测试，再显式执行：

`python -m tools.recycle_probe --run-native`

探针仅在项目 .tmp 中创建新的唯一模拟目录，生成一个待回收文本和一个未选择的对照文本，不接受任意现有路径作为删除参数。最终验证结果：

- Shell 删除前回调完成路径和状态检查，强制回收模式；
- PostDeleteItem 返回成功 HRESULT 和回收站条目，程序确认为回收成功；
- 被选模拟文件原路径消失，未选对照文件内容保持不变；
- 索引同步为缺失，本机删除记录为成功；
- 不调用永久删除或旧接口作为失败回退。

原生接入期间修正了 pywin32 常量位置、COM 进度回调包装和非零成功 HRESULT 的处理。一次早期探针因成功码识别过严被记为“待核对”，只读检查确认该模拟文件在回收站；修正后新的独立探针成功。本报告不把早期未确认结果计为成功。

真实原生验证只在 Windows 11 上进行。默认 pytest 的“回收”使用夹具内隔离区模拟，不碰系统中既有文件；适配器协议测试用模拟 Shell 验证否决和回执。Windows Server CI 不运行实际回收探针，也不代表 Windows 10 桌面兼容性已验证。

## 范围与已知限制

- Windows 10 **待验证**。没有执行正式打包或发布。
- 目录用途按已知相对结构识别，不推断联系人/群名，不保证包含全部聊天记录或全部图片。无法确认的目录只读并保留原名。
- 删除仅限已确认普通文件存储区域和允许的常见格式；数据库、配置、缓存、msg/attach、专有附件、隐藏/系统文件、链接、目录、非本地固定 NTFS 等对象拒绝。
- 本轮没有可信归档副本登记，因此外部归档副本不允许删除，也不提供自动“保留一份”辅助。所有原始附件必须由用户主动选择并确认路径引用风险。
- 文件状态仍可能受并发程序影响。程序在准备、固定句柄后和 Shell 删除前再次校验；写入占用或状态变化会跳过/失败。用户取消不会撤销已经确认完成的前项。
- Shell 未确认但原路径已消失时只标记待核对，不宣称可自动恢复。移入回收站不代表空间已经释放，系统回收站本身可能被用户或系统清理。
- 本机删除记录随元数据备份保存。恢复旧备份会恢复当时的记录，恢复前的自动备份保留恢复前状态以供核对；记录并非文件内容备份。
- 不对真实微信目录进行删除实验。原始个人扫描结果、索引、哈希缓存、删除日志、回收探针结果及构建产物不上传 GitHub。
